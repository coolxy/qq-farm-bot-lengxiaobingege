# 事件推送与掉线判定

本文说明账号掉线时「什么时候推、什么时候不推」的判定逻辑，以及会话保活与推送通道的工程约束。实现位于 `core/src/runtime/event-notify.ts` 与 `core/src/runtime/wechat-auto-relogin.ts`。

## 为什么不能「一断就推」

微信连接的断开是常态而非异常：换码、心跳重连、服务端抖动都会拉断 WebSocket，而绝大多数情况会在几十秒内自动重登成功。若每次断开都立刻推送，用户一天会收到几十条「已离线」，真正需要扫码的那次反而被淹掉。

因此掉线提醒改为**延迟判定**：先挂起，把时间让给自动重登，只在确定救不回来时才打扰。

## 判定流程

```text
连接断开（disconnect / ws_error / kickout）
  │
  ├─ 终态原因？ ── 是 ──> 立即推送（不等窗口）
  │                        auto_relogin_failed: / no_session / offline_timeout / kickout_limit
  │
  └─ 否（过程态）──> 挂起 150 秒
                       │
                       ├─ 期间恢复在线 ──> 取消挂起，完全静默
                       ├─ 期间转终态 ────> 立即推送，清掉定时器
                       └─ 到期仍未恢复 ──> 兜底推送（附「已等待 150 秒」说明）

已经推送过「已离线」的账号，恢复连接时补一条「农场已恢复在线」，形成闭环；
没推送过的不补——150 秒内的抖动恢复不该产生任何通知。
```

三条路径互斥，靠 `pendingOffline` 表（按账号 id）保证同一账号只有一条挂起项。同账号再次断线会重置计时，但保留最初那条原因，避免抖动把「断线」改写成「重登失败」。

### 谁负责通知用户

登录成功、扫码登录、服务重启都**不推送**——这些只说明服务在正常工作。worker 侧的登录提醒已移除，所有通知收敛到本模块：只有「确实推送过掉线」这一件事，才值得在恢复时再告诉用户一次。

### 为什么窗口是 150 秒

自动重登自身有三次重试（30s + 12s + 30s）。实测一次完整失败链耗时 43 秒，加上首次重试前的等待与换码开销，最坏约 92 秒。窗口取 150 秒留出约 60 秒余量，同时短于「用户开始怀疑是否卡死」的心理阈值。

正常失败会在 75~90 秒由终态推送接管并清掉定时器，150 秒这条只负责「既不成功也不失败」的卡死场景，日常几乎不会走到。

## 不重复打扰

| 机制 | 行为 | 目的 |
| --- | --- | --- |
| 同类去重 | 同账号、同类别（`disconnect`/`kickout`/`relogin_failed`/`offline_timeout`/`ws_error`）10 分钟内只推一条 | pushplus 对重复内容直接返回 `code 999` 丢弃，与其被服务端判重，不如自己先省掉 |
| 终态后静默 | 已推送过的账号，窗口内再来的过程态消息不再挂起 | 避免终态推送之后又来一条 `disconnect`，到期再喊一次 |
| 恢复即清零 | 收到连接恢复事件时清掉该账号的去重记录 | 真掉线两次（间隔很短）时仍能各推一条 |

## 推送通道

- **串行队列**：登录提醒、神秘商人到货、掉线提醒可能同一刻触发，pushoo 系渠道对同 token 并发会返回「服务端验证错误」，因此所有推送进入单一队列依次发送
- **失败重试一次**：首次失败后等 2 秒再发一次，仍失败才记错误日志
- **配置错误只提示一次**：渠道未配 token、webhook 缺地址等问题，同一原因只写一条日志，改配置后重新校验

## 会话保活

微信会话有效期 7200 秒。系统每小时整点刷新一次，判据是「上次刷新所属的小时数与当前小时不同」，因此不会因为进程重启而重复刷新。

- 成功后静默，不占推送配额（`PUSH_SESSION_REFRESH_SUCCESS = false`）
- 失败才推送，避免用户以为一切正常
- 无可用会话时补发 `no_session:` 终态提醒，这条走立即推送路径

账号记录上新增 `wxSessionRefreshedAt` 字段，仅用于小时比较；缺失时回退到 `updatedAt` 作为基线。

## 停机抑制

改代码、重启服务、`stop.sh` 都会主动断开连接。若不加区分，每次运维都会换来一条「农场已离线」。

主进程收到 `SIGTERM`/`SIGINT`/`SIGHUP` 时置位 `runtimeStopping`，此后：新断线不挂起，已挂起的到期也不推。该标记只在本进程生命周期内有效，不做持久化。

同时，worker 主动停止（用户点停止、重登前的 `stopWorker`）不会进入提醒流程——`disconnect` 与 `kickout` 分支都先检查 `worker.stopping`。

## 参数与测试

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `offlineDeferMs` | `150_000` | 延迟判定窗口，可注入 |
| `offlineDedupeMs` | `600_000` | 同账号同类去重窗口，可注入 |
| `SESSION_REFRESH_INTERVAL_MS` | `3_600_000` | 会话刷新周期 |

常规测试用毫秒级窗口覆盖状态机；真时间验证由 `core/tests/event-notify-offline-slow.test.js` 承担，默认跳过，需要时：

```bash
SLOW_OFFLINE_E2E=1 pnpm -C core test            # 真等 150 秒，约 3 分钟
SLOW_OFFLINE_E2E=1 OFFLINE_E2E_MS=3000 pnpm -C core test   # 缩短窗口，逻辑等价
```

慢测覆盖 13 项：到点必推且只推一条、窗口内恢复不推、抖动从最后一次断线重算、终态立即推且晚到过程态不重推、停机标记抑制已挂起提醒、取消停机后恢复推送。
